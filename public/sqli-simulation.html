📖 What is SQL Injection?

SQL Injection (SQLi) is an attack where malicious SQL code is inserted into input fields to manipulate the database query.

❌ Vulnerable Code

// PHP - BAD: string concatenation $query = "SELECT * FROM users WHERE username = '' . $_POST['username'] . ''"; // If user types: admin' OR '1'='1 // Query becomes: SELECT * FROM users WHERE username = 'admin' OR '1'='1' // Result: returns ALL rows ❌

✅ Secure Code (Laravel)

// PHP Laravel - GOOD: prepared statement $user = User::where('username', $input)->first(); // Behind the scenes Laravel uses: SELECT * FROM users WHERE username = ? -- parameterized // Input is safely bound as data, NOT code // Result: safe ✅

🛡️ How SupplyVaksin Is Protected

  1. Laravel Eloquent ORM — All queries use parameterized statements automatically. User::where('username', $input) binds $input as data, never as SQL code.
  2. Input Validation — Controllers use $this->requireFields() and type checking. Invalid input is rejected before reaching the database.
  3. Role-Based Access Control (RBAC) — Middleware checks authentication and authorization on every endpoint. Nurses can't access admin endpoints.
  4. CHECK Constraints — Database-level constraints like users_role_check ensure only valid values are stored, preventing injection payloads from persisting.
  5. Session Security — Session IDs are random strings. Session data is stored server-side in PostgreSQL, not in cookies.
// Example: SupplyVaksin's AuthController — SAFE login $user = User::with('facility') ->where('username', $username) // ← parameterized ->first(); if (!$user || $password !== $user->password) { return $this->fail('Invalid username or password.', 401); } // Even if attacker sends: admin' OR '1'='1 // Laravel safely treats it as a literal string // Query becomes: WHERE username = "admin' OR '1'='1" // No matching user → login fails → attack blocked ✅
